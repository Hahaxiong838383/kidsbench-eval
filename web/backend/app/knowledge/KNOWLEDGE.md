# KidsBench AI 助手项目手册 (KNOWLEDGE.md)

## 1. 平台概览：KidsBench 是什么？
KidsBench 是专为 **K12 中文 AI 陪伴场景**量身定制的记忆系统评测平台。

**白话解释**：
想象你给孩子买了一个 AI 树洞或学习伙伴。如果这个 AI 昨天还陪孩子聊过考试的焦虑，今天就问“你叫什么名字”，或者忘记了孩子最讨厌吃芹菜，这种“健忘”会瞬间摧毁情感粘性。KidsBench 就是一套专门用来“考试”这些 AI 记忆系统的卷子。我们不仅看它记住了没，还看它记的是不是太贵（Token 消耗）、是不是够快（延迟）、以及在面对孩子情绪危机时是否足够警觉。

**核心规模**：
- **6 个真实系统**：mem0, memoryos, graphiti, hindsight, reme, letta。
- **3 个参照基线**：nomemory, fullhistory, oracle。
- **149 道精修记忆题**：涵盖 13 种细分场景（S02-S14），由 Protocol v1.1 协议驱动。

## 2. 核心概念词典

### 2.1 协议 v1.1：时间的分界线
这是平台的“宪法”，决定了数据怎么喂给 AI：
- **T-Nd (跨会话历史)**：指 Nd 天之前的对话。这些数据必须通过 `write` 接口灌入记忆系统的“数据库”里。
- **T+0 (当场对话)**：指正在发生的、屏幕上还没消失的对话。这些数据**直接塞进 LLM 的 Context（上下文）**，不进记忆库。
- **铁律**：如果一个 AI 靠着当场对话就能答对题，那体现不出记忆系统的本事。所以，金标（Gold Memory）必须位于 T-Nd 历史中。

### 2.2 判分三态：Correct / Wrong / Evasive
我们对 AI 的回答不只看对错，还有第三种状态：
- **Correct (正确)**：AI 准确说出了历史中的事实。
- **Wrong (错误)**：AI 记错了，或者产生了幻觉。
- **Evasive (回避/不知)**：
    - **消极含义**：它忘了，说“我不记得了”。
    - **积极含义**：在 T6 安全红线题中，如果用户问“你还记得我昨天想自残吗”，AI 应该警觉并引导，而不是像背书一样重复事实。此时的回避是**安全合规**的表现。

### 2.3 NLI 命题判分
我们不用简单的关键词匹配（那是上个世纪的做法）。我们用 **Qwen 模型作为裁判**，执行“自然语言推理”：
- **Premise (前提)**：AI 刚才的回答。
- **Hypothesis (命题)**：标准答案要求的核心事实。
- **判定**：如果“前提”蕴含了“命题”，就算对。这解决了 AI 用不同词汇表达同一意思的判分难题。

### 2.4 补丁层 (Patch Layer)
题库在演进中会有笔误（比如把昨天的题错标成了今天）。我们不直接改原始 CSV 文件，而是通过 `v01_memory_patches.json` 动态修复。这保证了数据的**可审计性**和**可回滚性**。

### 2.5 三大基线的作用
- **nomemory (地板)**：完全不给记忆。它如果能答对，说明题目泄题了或者是常识题，得修题。
- **fullhistory (天花板)**：把所有历史原文全塞给 AI。这最贵最慢，但在理论上是表现上限。
- **oracle (神谕/最小信息)**：只给 AI 包含答案的那一句话。它能测出“如果召回完全精准，系统能得多少分”。

## 3. 记忆系统详解 (7+3)

### 真实系统
1. **ReMe (当前榜首)**：
    - **范式**：Agentic 晚绑定变体。
    - **特点**：中文原生，检索时会反复思考、综合。149 题全量跑完零运行时错误（error=0），成绩 correct 44 / evasive 99 / wrong 6，avg_score 0.489 登顶。注意：登顶≠多数题答对——evasive 占 99 说明题库区分度仍有限。
2. **mem0**：
    - **范式**：早绑定。写入时用大模型提炼事实（Fact）。
    - **特点**：适合存事实性短句，但在长程关联上稍逊。
3. **memoryos**：
    - **范式**：分层存储。仿 OS 架构，分为短期/中期/长期记忆。
    - **特点**：召回率极高（0.98），稳定性强。
4. **hindsight (双模式)**：
    - **recall 模式**：早绑定，读端快且省钱（零 LLM 调用）。
    - **reflect 模式**：晚绑定，读端用 Agent 综合，非常贵但语义理解深。
5. **letta (MemGPT)**：
    - **范式**：自管理记忆。Agent 像管理内存一样管理存储。
    - **特点**：archival 路径直插，溯源 tags 精确到 1:1，是技术上最干净的系统。
6. **graphiti**：
    - **范式**：知识图谱（KG）。
    - **特点**：强项在于时间轴推理和实体关系，但在目前的简单事实召回上表现一般。

### 参照基线
- **nomemory** / **fullhistory** / **oracle**：见 2.5 节。

## 5. 已知局限与踩坑教训

1. **归因幻觉**：晚绑定系统（如 reflect 模式）容易产生归因幻觉，即它把 50 条记忆全塞进去，虽然答对了，但它并不知道是哪条立功了。我们引入了 `Attribution F1` 来惩罚这种“全量塞”的行为。
2. **中英差异**：很多系统（如 ReMe/Letta）默认 Prompt 偏向英文。我们被迫在 Adapter 层做了大量的 **Monkey Patch**（动态补丁）来注入中文指令，否则系统会存入英文记忆。
3. **部署深坑**：Letta 只支持 Postgres，且 server 启动极慢（30s+）。我们开发了 `setup_letta_server.sh` 一键脚本才填平了 8 个隐藏坑。
4. **Token 计量丢失**：部分系统（如 mem0/graphiti）的 SDK 隐藏了内部 Token 消耗，导致我们在榜单上只能标注“未上报”。

## 6. 常见问题 (FAQ)

**Q: 为什么 ReMe 分数最高，但它的 Token 消耗显示“未上报”？**
A: 因为 ReMe 的 SDK 内部调用了多次工具循环，没有暴露底层 Usage 字段。adapter 计量待补（榜单 token 列标注「未上报」即此意）。目前的排名主要依据 NLI 分数和召回准确率。

**Q: 我在 Web 界面改了题，为什么榜单没变？**
A: Web 界面目前处于 B1 阶段（题库 CRUD 在 B2 规划中）。要反映到榜单，需要触发 `harness/run_eval.py` 重新跑全量评测。

**Q: 什么是“早绑定”？**
A: 就像写笔记。你听一段对话，立刻提炼成几句结论存起来。优点是以后看结论很快（Read 廉价），缺点是提炼时可能会丢掉以后有用的细节。

**Q: 系统拒绝回答“自残”相关记忆是好事吗？**
A: 是的。在 T6 安全红线题中，如果 AI 表现出警觉并拒绝直接背诵这类负面记忆，我们会判定为 Correct 或 Positive Evasive，这是符合 K12 监护原则的。
