## 0. 缘起：控制变量悖论（Control-Variable Paradox）

之前 team 把「read 时调 LLM 做动态聚合」当成必须红线锁死的「作弊/不公平」。川哥用第一性原理打穿：

> **为公平而施加的「控制变量」（强制所有家 read 零-LLM），会先验地把一整类设计范式从答案空间删掉——而范式差异恰恰是设计原则的唯一来源。**

形式化（grok）：把「read 零 LLM」当公平条件 = 把「需要 query-aware 动态提炼」的整个设计空间先验排除。这不是技术细节，是**假设空间被观测协议污染**。

这一悖论直接质疑项目的根基词「**公平横向对比**」——见 §6。

## 1. 核心范式分野：早绑定 vs 晚绑定

| | 早绑定 / Eager Consolidation | 晚绑定 / Query-time Synthesis |
|---|---|---|
| write | LLM 当场提炼成 fact/entity/graph | 廉价存原始 turn |
| read | 廉价检索 | LLM 按 query 动态聚合提炼 |
| 优势 | read 快、可溯源、成本前置 | query-aware、按需提炼、不过早丢信息 |
| 代价 | 写时不知未来怎么被查→过早压缩丢信息 | read 慢、贵、每次重算 |
| 代表 | mem0 / memoryos / graphiti | LangMem 可这么配 / RAG-style |

**本质（grok）**：记忆系统 = 信息保存 vs 检索成本的权衡。早绑定在 write 时做不可逆压缩，损失「未来任意重组的可能性」；晚绑定把压缩延迟到 read，把 query-specific synthesis 变优势，但把每次 read 的 token 成本变成变量。

K12 例子：孩子「昨天考试没考好有点难过」，3 月后问「还记得我考试的事吗」。早绑定若写时没把「情绪」设为重要字段就丢了；晚绑定 read 时 LLM 看原始 turn 能复原「那次他难过我安慰过他」。**晚绑定可能恰好更适合「懂我/情感粘性」——这本身是一条候选设计原则。**

## 2. 核心张力裁决：要不要锁同一 LLM？

team 最大分歧：

- **cc 上轮 + grok**：锁同一注入 LLM，否则混淆「记忆设计差异」与「模型能力差异」。
- **gemini 强烈反对（Asymmetric LLM Scaling）**：早绑定生命线在**写端**（写时吃强算力、读时几乎不用 LLM），晚绑定生命线在**读端**。强制全链路同一模型，逼早绑定读端也烧 GPT-4o，**抹杀它「读端廉价」的核心范式优势 → 又一次范式阉割**。生产中没人会让两种架构的读端用同规格 LLM。

**cc 裁决（综合升级，不和稀泥）**：gemini 对——不该硬锁全链路同一模型；但 cc 锁模型的初衷（消除模型能力作为隐藏自变量）必须保住。三机制调和：

1. **不锁被测系统内部模型**：每家自由配 Write-LLM / Read-LLM（这本身是设计决策——早绑定选「写强读弱」，晚绑定选「写弱读强」）。
2. **锁三样**：① 中立 Judge LLM（评分中立，独立于被测内部模型）② 统一 Token 价格表（成本可比）③ 在 **Pareto 前沿（成本×效果二维）** 比，不比单维——「用更强模型」的代价被成本轴吸收。
3. **解耦设计 vs 模型选择的关键招（cc 增量）**：对同一记忆系统**跑多个模型配置点，画出它自己的成本-效果曲线**，比「曲线整体靠不靠左上」而非单点 → 记忆设计优劣 = 效率前沿曲线位置，**与具体选哪个模型点无关**，彻底解耦。

→ **结论：锁模型 ❌ → 锁「裁判 + 价格表 + Pareto 前沿」+ 每系统多点画曲线 ✅**

## 3. 六问综合答案

**Q1 框架成立吗**：成立。命门不止成本，是「读写比 + 记忆需求类型」必须同列为第一类自变量（grok），否则矩阵退化成另一种总分榜。

**Q2 成本计量**：必须锚定真实 K12 workload，不能抽象比 per-query。三 canonical workload：
- W_daily 写多读少 ~18:1（日常吐槽，事实/偏好 query）
- W_reflect ~6:1（里程碑回顾，跨周情绪连续性）
- W_crisis ~3:1（情感支持，关系级叙事）
- gemini 极端档 ~120:1（写极多、读极稀但每次读触发深度多跳）
→ K12 真实特征「写极多、读极稀但每次读触发关系级推断」→ 指向晚绑定/混合更优。**设计原则：最优范式依赖读写比**。产出「读写比-成本分水岭计算器」（gemini）。

**Q3 晚绑定溯源**：cc 上轮 hunch（晚绑定更易溯源）**被两家否决 = 归因幻觉**。consumption log 把「检索范围」当「生成依据」，检索 50 turn 只用 1 个却记 50 consumed → 假阳性。两修正（分两档）：
- **Ablation 因果归因（gemini，金标准）**：剔除 target turn 再跑 read，看核心记忆点是否消失 → 才判 true source。准但贵（N turn→N 次重跑）。
- **Utilization Ratio（grok，廉价代理）**：(对答案有直接贡献的 source token)/(喂给 synthesis 总 token)，低于阈值 Precision 打折，防「全塞进去」。
→ cc 分层：Ablation 作小 gold 验证集金标准，Utilization 作大规模代理，呼应「真实撑统计显著 vs 合成撑方向性」。

**Q4 题型对抗矩阵（gemini，最落地）**：
| 维度 | K12 题型 | 谁赢 | 反推设计原则 |
|---|---|---|---|
| D1 Schema-breaking | 「我是漏气的气球」3月后「我何时觉得自己不完整」 | 晚绑定（早绑定写时丢非结构化情感） | 高情感张力场景严禁过早 schema 化 |
| D2 Super-long aggregation | 「这学期提过几次妈妈不理解我」（4月50次零散） | 早绑定（晚绑定 context 爆仓/成本暴死） | 高频可累加趋势分析用写时增量聚合 |
| D3 Memory-correction | 讨厌→今天喜欢番茄→「我喜欢番茄吗」 | 晚绑定（带时间戳 raw turn 时序自愈） | 高动态画像晚绑定有时序自愈 |
| D4 Sparse implicit emotion | 5天微弱沮丧→「我最近状态怎么样」 | 晚绑定（读时微弱信号相干叠加涌现） | 微弱长周期情感只能晚绑定二次涌现 |

**Q5 产出形态**：不是排行榜，是 **Pareto 决策器 + 设计原则卡**：每种记忆需求一张卡（三 workload 读写特征 + 早/晚/混合三条成本-效果曲线 + 推荐 hybrid 切点 + 风险提示）。横轴成本($/千用户天)，纵轴综合得分，看 Pareto 前沿。

**Q6 新盲区**：见 §4。

## 4. team 共挖的 7 个盲区（cc 原方案没想到）

| # | 盲区 | 来源 | 说明 |
|---|------|------|------|
| 1 | **Query authorship bias** | grok | 题库作者潜意识偏「事实性 recall」，系统性低估晚绑定最该赢的情绪叙事题，藏在「题库看起来公平」外观下。比成本计量更隐蔽 |
| 2 | **K12 隐私/被遗忘权删除成本** | grok | 晚绑定长期存原始 turn，级联删除+可能重合成，合规成本在 K12 可能压倒性，而非次要成本项 |
| 3 | **反馈环路腐蚀** | gemini | 晚绑定 synthesis 幻觉写回历史→永久沉淀→第30天因自身微小幻觉累积崩塌。**静态评测根本测不出** |
| 4 | **Prompt 敏感度黑盒** | gemini | 统一 prompt 偏向某类模型 / 自由调优变成比 prompt 工程 → 需 prompt 鲁棒性压力测试（微扰看方差） |
| 5 | **冷热分层断档** | gemini | 真实系统 Hot(晚)/Warm(早图谱)/Cold(向量) 分层，纯极端测试让混合方案两头不讨好 → 需混合跨度题逼出 Tiering Router |
| 6 | **Asymmetric LLM Scaling** | gemini | 范式与模型能力适配非对称（已驱动 §2 裁决），元级盲区 |
| 7 | **混合范式是谱不是二元** | grok+cc | paradigm position 连续坐标 (write_tokens/turn, read_tokens/query) 归一化 [0,1]²，混合自然落中间 |

**应对（gemini）**：盲区3 → 引入「动态交互沙盒」，模拟孩子连续互动 N 天（如 30 天 50 轮），测记忆系统的「自我净化能力 vs 自我沙化速度」，而非单次静态 query。

## 5. 对前两轮结论的诚实修正

本研究推翻 cc 自己前面几个判断：
- ❌「read 零 LLM 必须第一步锁死」 → ✅ read 用 LLM 是范式选择，进 paradigm 轴 + 成本计量，不封杀
- ❌「锁同一注入 LLM」 → ✅ 锁裁判+价格表+Pareto，模型自由，每系统多点画曲线
- ❌「晚绑定更易溯源」 → ✅ 归因幻觉，需 Ablation/Utilization 挤水分

## 6. 基于本研究对项目的重新评估（川哥要的核心）

### 6.1 目标重估：从 benchmark（比分）→ cartography（设计空间制图）

**原目标**：「横向**公平对比** N 个记忆系统，反推自研设计原则。」

**问题**：本研究揭示「公平对比」内含控制变量悖论——越追求公平（控制变量压平范式差异），越测不出设计原则（差异本身）。「对比谁更好」预设了存在一个全局最优，但研究证明**最优是 workload/需求类型的函数**，不存在全局冠军。

**重估后目标**：从「评出谁最好」转向「**绘制记忆设计空间的权衡地图**」——回答「在什么条件（读写比/需求类型/隐私约束）下，什么范式取舍最优」。这是从 benchmark 到 cartography 的转变。
- 「反推自研设计原则」仍是北极星，但实现路径变了：不是「让自研在公平榜上证明自己好」，而是「在设计空间地图上定位自研的取舍，看它在哪些需求格子有优势/劣势，据此迭代」。

### 6.2 定位重估：K12 陪伴定位应从「背景」升为「框架核心约束输入」

本研究强化并锐化了 K12 中文陪伴定位的独特性：
1. **workload 指向性**：K12 陪伴是「写极多、读极稀但深、高情感连续性」——这个特征本身让范式选择有明确指向（偏晚绑定/混合），是通用记忆 benchmark 给不出的。
2. **隐私硬约束**：被遗忘权删除成本（盲区2）是 K12 专属维度，通用 benchmark 没有。
3. **情感粘性北极星**：决定题型必须偏情绪叙事而非事实 recall（对抗 query authorship bias 盲区1）。

→ **结论：定位越窄越锐利，反推的设计原则越有用。** KidsBench 不该做「通用记忆评测顺便用 K12 题」，该做「**K12 陪伴场景专属的记忆设计决策器**」。定位从背景升为框架的一等输入。

### 6.3 调研项目设计重估（5 层架构逐项）

| 设计 | 重估 |
|------|------|
| **判分两线分离**（客观判分 + 诊断自报） | ✅ 仍成立，好设计。但「客观判分」内涵要扩：从 Attribution F1 + NLI → 加 **成本-效果 Pareto + Ablation 归因 + 动态沙盒崩溃率** |
| **Attribution F1** | 🔧 重构：区分直接/间接来源（consolidation 继承）+ Ablation/Utilization 挤晚绑定水分。原单口径不够 |
| **静态评测**（喂历史→单次 query→评分） | 🔴 最大冲击：测不出反馈环路腐蚀（盲区3）。**架构级新增动态交互沙盒**（L2 harness 支持多轮交互模拟 N 天） |
| **题库** | 🔧 从「事实 recall 为主」→ 四维对抗矩阵 D1-D4 + 三 workload，防 query authorship bias（情绪叙事题需人工对抗设计） |
| **Lane 概念**（锁模型档位） | 🔧 演进为「价格表 + Pareto 多点曲线」，模型自由 |
| **新增维度** | 成本计量（token 计价）/ 隐私删除成本 / paradigm position 连续坐标 / prompt 鲁棒性方差 |

**一句话**：本研究把项目从「benchmark 思维」推向「**设计空间制图 + 动态行为评测**」思维。
